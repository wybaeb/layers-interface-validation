# Синтетический набор для проверки интерфейса · проект «Пульс» (веб-MVP)

Сквозной проект курса. Основа — материалы кейса «Пульс»: кейс-библия, User Flow, Screen Flow, дерево информационной архитектуры и отчёт о проверке дерева.
Всё вымышленное: участники и реплики — синтетика, помечена. Реальные интерфейсы не используются — «вырезки» нарисованы как бумажные кусочки с чужим визуальным языком (светлые iOS-подобные контролы и тёмные виджеты трекеров).

- `screens/` — шесть отдельных SVG-экранов; у ключевых элементов устойчивые `id` (`btn.resolve_conflict`, `chips.quick`, `nav.chat` …) для поля `target_id` в отчёте; 390 × 844 с устойчивыми ID экрана в имени файла (`S-TODAY__Сегодня.svg` …): векторная заготовка Screen Flow (рамка, верхний бар, топ-бар из 4 пунктов по Screen Flow) плюс бумажные вырезки элементов. Экраны: S-TODAY Сегодня (S5), S-CHAT Чат (S6), S-TRENDS Тренды (S7), S-SETTINGS Данные и настройки (S8), S-CONFLICT Разбор конфликта (S9), S-IMPORT Загрузить экспорт (S4).
- `screen_flow.svg` — дерево экранов (Screen Flow) из тех же кадров, с дублем входа «Чат → Разбор конфликта».
- `ia.md` — информационная архитектура, сохранённая из тренажёра «Информационная архитектура продукта».
- `tasks.md` — шесть заданий с допустимыми конечными ответами и сценариями.
- `questionnaire.md` — вопросы для показа статических экранов и формат ответов.
- `transcript.md` — обычный транскрипт без ручных маркеров; модератор естественно называет открываемые экраны, а агент собирает `screen_timeline.json`. В учебной записи есть подтверждённый разрыв между ожидаемым результатом, выбранным действием и фактическим переходом; конкретное изменение агент должен вывести из цитат и экранов самостоятельно.

Короткий прогон из корня студенческого репозитория: `python3 interface_validation.py`.
